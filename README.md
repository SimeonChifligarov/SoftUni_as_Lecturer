## Overview

This repository contains material accumulated through my work as a **programming lecturer**, primarily around SoftUni's **Programming Basics** curriculum.

It combines several types of content:

- Lecturer preparation before classes
- Programming theory and practical examples
- Problems solved live during lectures
- Problems solved during exercise sessions
- Personal teaching notes
- Alternative solutions and approaches
- SoftUni Judge exercises
- Additional practice problems
- Exam preparation
- Historical course iterations
- Python and JavaScript implementations

The goal of the repository is broader than simply storing correct solutions.

It documents the process of **preparing, explaining, demonstrating, and reinforcing fundamental programming concepts** for people taking their first steps in software development.

---

## Repository Goals

The repository serves several complementary purposes.

### Teaching Reference

Maintain an organized archive of examples, exercises, explanations, and solutions used during course preparation and classroom teaching.

### Programming Fundamentals

Demonstrate fundamental programming concepts through progressively more complex problems rather than isolated syntax examples.

### Problem-Solving Practice

Show how programming problems can be decomposed into:

1. Inputs
2. Required outputs
3. Conditions
4. Repetition
5. Intermediate calculations
6. Edge cases
7. Final implementation

### Course Preparation

Preserve preparation work for lectures, exercises, additional problems, and exams.

### Historical Archive

Keep material from different course editions so that examples and teaching approaches can be compared and refined over time.

# Exam Preparation

The repository contains a dedicated Python exam-preparation collection with solved Programming Basics exam problems.

These materials are particularly useful after completing the standard curriculum because exam problems often require several concepts to be combined within the same task.

A productive way to use them is:

1. Read the problem independently.
2. Identify the required inputs and outputs.
3. Design the algorithm before coding.
4. Implement your own solution.
5. Test it against multiple cases.
6. Submit it to Judge when applicable.
7. Only then compare it with the solution stored in this repository.

The objective should be to understand **why the solution works**, not merely to reproduce the implementation.

# How to Use This Repository

## For Students

If you are learning programming, use the repository primarily as a **reference after attempting a problem yourself**.

A recommended workflow is:

1. Study the corresponding programming concept.
2. Read the problem carefully.
3. Solve it independently.
4. Test your implementation locally.
5. Submit it to Judge where applicable.
6. Debug unsuccessful attempts.
7. Compare your final approach with the repository.
8. Look for differences in readability, structure, and algorithmic reasoning.
9. Reimplement the problem without looking at either solution.

This approach produces significantly more learning than copying an existing answer.

# Teaching Philosophy

Programming Basics is not primarily about learning the syntax of a particular programming language.

The more important objective is learning how to **translate a problem into a sequence of precise computational steps**.

A beginner should gradually learn to ask:

- What information do I receive?
- What result must I produce?
- Which values do I need to store?
- Which calculations are required?
- Which decisions must the program make?
- Which operations need to be repeated?
- When should repetition stop?
- Which edge cases can change the result?
- How can I verify that my algorithm is correct?

Python and JavaScript are tools for expressing those decisions.

The transferable skill is **problem solving**.

For that reason, many exercises in this repository deliberately focus on relatively small programs. Their purpose is to isolate fundamental concepts and allow the learner to reason about program behavior clearly.

# Academic Integrity

Solved programming exercises are most valuable when used **after making an independent attempt**.

If you are currently enrolled in a course or preparing for an assessment, avoid using this repository simply to copy answers.

Instead:

- Attempt the task independently
- Debug your own solution
- Compare approaches afterward
- Understand every line you reuse
- Respect the rules of your course, examination, and learning platform

Learning to program requires developing the ability to solve unfamiliar problems without already having the implementation in front of you.
